# Seed runs replay arena sequences, not inputs

Bomb Blitz already derives every Run from a 32-bit Seed, and a Daily Run is just a Date-seeded Run. That made the Seed central to fairness but invisible to the player: a Run Record did not keep its Seed, a Daily Run could not be replayed after its date, and there was no way to share an arena sequence without both players starting on the same day. This slice makes the Seed a first-class part of the Run.

Decisions that future readers would otherwise have to guess at:

- **Every Run has a Seed, and every new Run Record stores it.** The Seed is the 32-bit value the run controller already receives. Records created before this slice migrate without a Seed and offer no replay; new records always carry one. This keeps one definition of "the run" instead of treating Seed Runs as a separate persistence path.
- **A Seed Run is a Run Mode, not a modifier.** It uses the same rules, upgrades, Techniques, scoring, and history as an Endless Run; only where the Seed came from differs. A Daily Run keeps its Daily Best. Replaying a Daily Run Record starts a Seed Run with the stored Seed because the original date and its Daily Best no longer apply.
- **A Seed Code is uppercase base36, 1–7 characters.** A 32-bit Seed becomes at most 7 base36 characters, which is short enough to type and copy. Input is case-insensitive and trims surrounding whitespace; values above `0xFFFFFFFF` are rejected. There is no decimal seed format, so a code can never be misread as two different numbers.
- **Replaying a Seed reproduces the arena sequence and draft offers, not the player's actions.** The simulation is deterministic from the Seed plus the intent stream. Without storing and replaying intents, a shared Seed gives the same stages and the same choices, not a ghost of the original run. Storing an input log is a separate feature and is deliberately absent.
- **A Share Link carries `?seed=<Seed Code>` and opens the Seed Run setup.** It does not auto-start a Run: the player still confirms, and the address bar is not a live mirror of the current Run. The link is generated on demand by the Copy Seed Link action. This avoids a refresh silently starting a new attempt and keeps the title screen the front door.
- **The profile moves to `bomb-blitz.profile.v3`.** v3 is authoritative once present. When v3 is absent, v2 is read once and migrated with every historical record Seed set to none; when both are absent, v1 is read once as before. A malformed v3 falls back to defaults rather than resurrecting v2 or v1. The old keys are never written.
- **There is no server, account, or seed verification.** A shared code is just a code. Nothing proves which code produced a score, and the game does not pretend otherwise.

**Considered Options**: storing an intent log for true ghost replays (far larger, and the umbrella spec keeps replay viewing out of scope); a server-backed leaderboard or link shortener (adds a backend to a deliberately static game); decimal seeds (unambiguous to machines, unfriendly to type and share); auto-starting a deep link (surprising, and breaks the "title is the front door" rule); keeping the profile at v2 with an optional field (a schema change pretending not to be one).

**Consequences**: a new Seed Run screen and Seed Code module; a profile v3 migration; a Seed line and Copy Seed Link action on game over; replay actions in Run History; `?seed=` parsing and URL cleanup; new browser verification paths. The existing Daily Run and Endless Run rules, arena generation, AI, upgrades, Techniques, and scoring are unchanged.
